Attention and the Transformer

2017: let every word look at every word

An RNN reads one word at a time and passes a memory along. Far-away words fade.

In 2017, the paper Attention Is All You Need dropped the RNN. Every token looks directly at every other token. This is self-attention.

Try it: switch between the two, and click any word.

But a word can't use every other word equally. How does it mix them?

✏️ Quick basics: a weighted average

A weighted average mixes things, giving each one a share. The shares add up to 100%.

Think of paint: more of one colour, and the mix looks more like it.

Try it: drag the sliders and watch the mix.
the mix

Self-attention builds each word's new vector exactly like this. Who decides the shares?

Query, key, value

Each token gets three vectors: a query (what am I looking for?), a key (what do I offer?) and a value (what I pass on).

Try it: click a word to make it ask. Each value is shown as a colour.
new “teddy bear”

🤔 Is there an everyday example?
A library search. The query is what you type. Each book's key is its title. The value is the book itself.
Titles that match your search best get most of your reading time.

Score = query · key. Softmax turns the scores into shares. The new vector is the weighted average of the values.

Where do these three vectors come from? First, one more tool.

✏️ Quick basics: multiplying by a matrix

A matrix is a table of numbers. Multiplying a vector by a matrix gives a new vector.

Each new number is a dot product: the vector · one column.

Try it: click a number in the answer to see where it comes from.

So a matrix turns one vector into another. That's how queries, keys and values are made.

Where queries, keys and values come from

Each token's embedding is multiplied by three matrices: WQ gives its query, WK its key, WV its value.

Try it: pick a token and see its three vectors.

The numbers in WQ, WK and WV are learned in training.

Now let's do this for all tokens at once.

The attention formula

Put all the queries in one matrix Q, all keys in K, all values in V. Then one line does everything:

Attention(Q, K, V) = softmax( Q KT√dk ) V
Try it: press each step. Click a row to follow one word.

That's self-attention. Now, the machine built around it.

The Transformer

The Transformer was made to translate: “A cute teddy bear is reading.” → “Un ours en peluche mignon lit.”

It has two parts:

  • The encoder reads the English and builds a meaningful embedding for each token.
  • The decoder writes the French, one token at a time, looking at the encoder's embeddings.

Let's walk through it from the bottom: what goes into the encoder?

Encoder input: one embedding per token

The text is split into tokens. Each token looks up its own row in a learned table: its embedding.

Try it: click a token to find its row.

The table has V rows and dmodel columns.

One problem: these embeddings say nothing about where each word is.

Self-attention can't tell word order

Self-attention looks at every word directly, so it never notices which word came first.

Try it: shuffle the words and watch the new “teddy bear”.
new “teddy bear”

The fix: add position information to each embedding before it goes in.

But how do you write “position 4” as a vector?

Position vectors, like a clock

A clock tells the time with hands turning at different speeds. Read them together, and you know the exact time.

A position vector works the same way: numbers that turn at different speeds as the position grows. It's added to each token's embedding.

Try it: move the position and watch the hands.

🤔 Why not just learn a vector for each position?
You can, and the paper tried it. But if training only had texts up to 500 tokens, there's no vector for position 501.
Turning hands work for any position, even ones never seen.

Nearby positions look alike, and far ones look different: just what we want.

Now each token knows what it is and where it is. Into the encoder!

Inside the encoder

The encoder has two layers, and the pair is repeated 6 times:

  • Self-attention: each token mixes in the tokens it needs. “teddy bear” takes in “cute”.
  • Feed-forward network: each token then thinks it over on its own.

What comes out: a vector per token that knows its context.

The English is understood. Now the decoder has to write.

The decoder

The decoder starts with just [BOS] (“begin”) and adds one French token at a time. Its layers, repeated 6 times:

  • Masked self-attention: each French token looks at the French written so far.
  • Encoder–decoder attention: it looks at the English, to see what to translate next.
  • Feed-forward network: thinks it over, like in the encoder.

At the top, how does a vector become a word?

Picking the next word

The top vector gets a score for every token in the vocabulary. Softmax turns the scores into chances. Then we pick one.

Try it: the decoder has only [BOS]. Pick the next word.

🤔 Isn't this the same softmax as in attention?
Same maths, different job.
In attention, it shares out a word's attention among the other words. Here, it shares out chances among all possible next words.

“Un” goes back in, and the decoder runs again for the next word, until it writes [EOS] (“end”).

That's the whole Transformer. A few tricks make it train well. First: masking.

Trick: masking

In training, the decoder gets the whole French sentence at once, to learn faster. But it must not peek at words it hasn't “written” yet.

Masking hides every later word, so each token only sees itself and the words before it.

Try it: turn the mask on and off. Each row is one token looking at the others.

That's why it's called masked (or causal) self-attention.

Next trick: why look just one way, when you can look several ways at once?

Trick: multi-head attention

One attention looks for one kind of thing. Multi-head attention runs several at the same time, each with its own WQ, WK, WV.

Try it: switch heads and see where “teddy bear” looks.

The paper used 8 heads. Heads aren't told what to look for: each learns it.

Two more tricks help a tall stack of layers learn.

Tricks: residual connections and layer norm

With 6 layers on top of each other, learning gets hard. Two small tricks help:

  • Residual connection: the layer's output is x + f(x). The layer only edits its input, instead of rewriting it from scratch.
  • Layer normalization: keeps each token's numbers a steady size from layer to layer.

Both help learning reach every layer, and make training faster and steadier.

The last two tricks stop the model from being too sure of itself.

Tricks: dropout and label smoothing

Dropout: in training, switch off a few random parts of the network each time, so it can't lean too hard on any one of them.

Label smoothing: don't ask for 100% on the right word. Language has many good answers.

Try it: the right word in training is “day”. Turn smoothing on.

    Those shapes like “8 × 512” matter. Let's see how they fit.

    Keeping track of sizes

    n tokens go in. The matrices change shape along the way, but what comes out is the same shape that went in: n × dmodel.

    Try it: change the number of tokens n.

    🤔 Why must queries and keys be the same length?
    Every score is query · key: multiply matching numbers, then add. That only works if both have the same count of numbers.
    So dq = dk (64 in the paper).

    Same shape in and out means layers can be stacked as high as we like.

    The English is encoded. Now let's watch the decoder write.

    End to end, part 2: the decoder writes

    Each round: the decoder reads what it has written so far (plus the English), picks one token, and adds it to its input.

    Try it: press Write the next token until it stops.

    Writing one token at a time, each one fed back in, is called autoregressive.

    What matters most

    If you remember two things about the Transformer:

    👀 Attention

    Every token looks directly at the tokens it needs. That's the paper's title.

    🧠 Feed-forward networks

    Where most of the weights live, and much of what the model learns.

    The rest are tricks to train it well. And, of course, it needs lots of good data.
